# 顔をほぼ 100% 隠すための計画

現状の顔隠しは YuNet 単体の毎フレーム検出と、見失ったときの hold で成り立っている。
正面顔にはよく当たるが、横顔・後頭部・遮蔽・ブレ・小さい顔で落ちる。落ちたフレームは
素顔のまま書き出される。この文書は、その取りこぼしを実用上ゼロに近づけるための段取りを
まとめたもの。

数値は断りのない限り**見積り**であり、この素材で測ったものではない。測る手順は 2 節に書いた。

---

## 0. 最初に：「100% 検出」は達成できない

顔検出器の再現率を 100% にする方法は存在しない。後頭部は原理的に「顔」ではないし、
真っ暗なフレームには手がかりが無い。単一の検出器の精度を追う限り、この計画は失敗する。

**目標を「検出率」から「被覆率」に置き換える。**

- 被覆率 = 顔の画素がマスクで覆われていたフレーム ÷ 顔が写っているフレーム
- 検出できなかった顔も、位置を推定して覆えれば被覆できる
- どうしても推定できないフレームは、**全画面をぼかす／その区間を捨てる**という逃げ道を用意する

この置き換えをすると、被覆率 100% は設計上到達可能になる。代わりに払うのは
「隠しすぎ（過剰マスク）」と「処理時間」で、どちらも顔バレより安い。

以下、施策を段階 A〜D に分ける。**A だけでも被覆率は大きく上がり、追加の依存が要らない。**
B 以降は依存とコストが増えるので、A を入れて実測してから判断する。

---

## 1. 現状の弱点

コードに即して並べる。番号は 3 節の施策と対応している。

| # | 弱点 | 該当箇所 |
| --- | --- | --- |
| 1 | **単一パスで、未来の情報を使っていない**。フレームを読みながらその場で検出・合成しているので、「この後 5 フレーム先で顔が再検出される」ことを知らないまま hold の位置を描いている | `render.py:239-250` |
| 2 | **hold が位置を固定する**。見失っている間、箱は最後に検出した位置に留まる。人が動いていれば顔だけ先に出ていく。hold は「静止している人」にしか効かない | `overlay.py:99-130` |
| 3 | **検出器が 1 種類**。YuNet は正面顔向けの軽量モデルで、横顔・後頭部・強い遮蔽・モーションブラーには構造的に弱い | `faces.py:129-152` |
| 4 | **検出解像度が既定 640px 固定**。1080p 素材では 1/3 に縮む。画面内で小さく写った顔は、縮小した時点で消えている | `config.py:47` |
| 5 | **未検出フレームに対する処置が無い**。時刻を記録して報告するだけで、そのフレームは素顔のまま出力される | `render.py:266` |
| 6 | **漏れを測る手段が無い**。正解データが無いので、設定を変えて良くなったのか悪くなったのか判定できない | — |

6 が一番効く。測れないまま 3 や 4 をいじると、体感で調整することになり、
「前より良くなった気がする」以上のことが言えない。

## 2. 先に測れるようにする

施策より先にこれをやる。ここを飛ばすと以降の判断が全部あてずっぽうになる。

### 2.1 指標

| 指標 | 定義 | 目標 |
| --- | --- | --- |
| 漏れフレーム数 | 顔が写っているのにマスクが顔領域を覆っていないフレーム | **0** |
| 最長漏れ | 漏れが連続した最長フレーム数 | 0（1 フレームでも顔バレは起きる） |
| 被覆率 | 覆えたフレーム ÷ 顔があるフレーム | 100% |
| 要目視時間 | 人が確認すべきと報告された区間の合計秒数 | 全長の 5% 以下 |
| 過剰マスク率 | 顔が無いのにマスクが出ているフレーム | 参考値（安全側なので許容） |

「漏れフレーム 0」を主指標にする。平均や率で見ると、1 フレームの漏れが 99.9% の被覆率に
埋もれてしまうため。

### 2.2 正解データの作り方

手で全フレームに枠を付けるのは現実的ではないので、二段構えにする。

1. **擬似正解をつくる**：速度を一切気にしない重量級の設定（全解像度・回転 TTA・
   アンサンブル・双方向補間、1 フレーム数秒かかってよい）で顔位置を出す。これを正解とみなす
2. **人が擬似正解を直す**：擬似正解を枠で焼き込んだ確認用動画を出し、間違っている箇所だけ
   手で直す。全フレームを見るのではなく、間違いを直すだけなので現実的な作業量になる

評価素材は 3〜5 本、各 20〜30 秒。**現状で漏れが起きる条件を意図的に含める**
（横を向く／手で顔を触る／逆光／奥に離れて小さくなる／速く動く／複数人が交差する）。
うまくいくケースを集めても意味がない。

`tests/make_fixtures.py` の合成素材は工程の検証には使えるが、検出の難しさを再現していない
ので、評価には実写を使う。

### 2.3 評価の入口

```
tamako eval --dataset eval/ --report eval_report.json
```

各素材について漏れフレーム数・最長漏れ・被覆率・処理速度を出し、前回結果との差分を表示する。
設定を変えたら必ずこれを通す。

## 3. 施策

### 段階 A — 構造を変える（最優先・追加依存なし）

現状の作りが持つ制約を外す。**新しいモデルを入れる前にこれをやる。**
検出器を強化しても、単一パスと位置固定 hold のままでは効果の半分を捨てることになる。

#### A-1 二段化：解析パスと描画パスを分ける

顔検出を書き出しから切り離し、先に全フレーム分を走らせて中間ファイルに落とす。

```
faces.jsonl  {"clip": "a.mp4", "frame": 1204, "t": 40.13,
              "boxes": [[x, y, w, h, score], ...]}
```

得られるもの：

- 未来のフレームの検出結果を使える（A-2 の前提）
- 検出をやり直さずにマスクの大きさ・位置だけ調整して再書き出しできる
  （現状は `scale` を変えるたびに全フレーム再検出）
- 検出結果を人が確認・修正できる（将来、手で枠を足す余地）

`render.py` の検出呼び出しを、この中間ファイルの読み込みに置き換える。

#### A-2 双方向の補間（最も効果が大きい）

ギャップの**前後**に検出があるなら、その間の位置は推定できる。

```
検出 ●━━━━ ギャップ 8 フレーム ━━━━● 検出
     位置を線形補間し、さらにギャップ長に比例して箱を広げる
```

- 前後にアンカーがある：線形補間（等速と仮定）
- ギャップが長いほど推定は外れる：**箱の拡大率をギャップ長の関数にする**。
  推定の不確かさを、位置の精度ではなく箱の大きさで吸収する
- 前後の距離が離れすぎている（別人の可能性）：補間せず、両方の位置の**和集合**を覆う

現状の hold（位置固定・前方向のみ）は、これの一番弱い特殊ケースにあたる。

#### A-3 端点の外挿

区間の先頭・末尾など、片側にしかアンカーが無い場合。直前の速度で外挿し、
外挿した秒数に比例して箱を広げる。`hold_sec` を超えたら段階 C の判断に回す。

#### A-4 オプティカルフローでギャップを埋める

補間・外挿は「等速で動いた」という仮定に過ぎない。実際の動きは映像から取れる。

`cv2.calcOpticalFlowPyrLK` で箱の内側の特徴点を追い、箱を実際の動きに沿って運ぶ。
OpenCV だけで足りるので追加依存はない。数フレーム程度のギャップなら、これがいちばん正確。

追跡が破綻したとき（点が散る・大きく縮む）は追跡を捨てて A-2 の補間に落とす。
壊れた追跡結果をそのまま信じると、マスクが顔から離れていくので必ず破綻判定を入れる。

#### A-5 トラックの再結合

長いギャップの前後を「同一人物」と繋げるかどうかの判断。位置・大きさに加えて、
箱の中の色ヒストグラムなど軽い特徴で照合する。繋がるなら A-2 で埋まる。
繋がらないなら、両方を独立のトラックとして扱い、**どちらも覆う**（安全側に倒す）。

**段階 A の期待効果**：短いギャップ（〜1 秒）の漏れはほぼ消える。現状の漏れの多くは
「数フレーム落ちてすぐ戻る」型なので、ここで大半が片付くと見ている。
長い未検出（後頭部で 10 秒など）は残るので、それは B と C で扱う。

---

### 段階 B — 検出の再現率そのものを上げる

段階 A を入れて評価し、まだ残る漏れの性質に応じて選ぶ。**全部やる必要はない。**

#### B-1 検出解像度を上げる

`detect_width` を 960〜1280 に上げる、あるいは縮小せず全解像度で検出する。
小さく写った顔に効く。素直だが、計算量は面積に比例して増える。

画面内で顔が極端に小さい素材（引きの画）が多いなら、**タイル分割検出**を足す。
画面を重なりを持たせて 2×2 に割り、各タイルを検出して結果を統合する。
全解像度検出と近い効果を、より安く得られることが多い。

#### B-2 入力側の TTA（テスト時変換）

同じフレームを変換して複数回検出し、結果の和集合を取る。

- **±25° 回転**：首をかしげた顔・寝転がった姿勢。YuNet は面内回転に弱い
- **CLAHE / ガンマ補正**：暗所・逆光。人の目には見えている顔が、検出器には潰れている
- **左右反転**：モデルの偏りを打ち消す。効果は小さめ

検出回数が変換の数だけ増える。全フレームに掛けるのではなく B-6 と組み合わせる。

#### B-3 検出器のアンサンブル

弱点の異なる検出器を並べ、和集合を取る。各検出器の閾値は**低め**にし、
統合時に NMS で重複を潰す。

| 候補 | 長所 | 短所・注意 |
| --- | --- | --- |
| SCRFD（insightface / onnxruntime） | 横顔・小顔・遮蔽に強い。現状の弱点を素直に埋める | 依存が重い。**学習済みモデルの利用条件を要確認**（非商用限定のものがある） |
| MediaPipe Face Detection | 導入が軽い。Apache-2.0 で条件が明快 | YuNet と弱点が似ており、上積みが小さい可能性 |
| YOLO 系顔検出 | 再現率が高い | Ultralytics は AGPL-3.0。配布形態次第で影響が出る |

**採用前にライセンスを確認すること。** この道具をどう配るかで許容範囲が変わる。
迷うなら MediaPipe から試すのが安全。

#### B-4 頭部検出を足す（後頭部・横向き対策）

**顔検出器では後頭部は原理的に取れない。** 後ろを向いた人を隠したいなら、
検出する対象を「顔」から「頭」に変える必要がある。

- 頭部検出モデル（CrowdHuman の head 注釈で学習したもの）を使う
- **骨格推定から頭の位置を割り出す（B-5。後頭部にはこれが本命）**
- 人物検出をして人物枠の上部を頭とみなす。粗い。人が屈む・座る・手を上げると
  枠の上端が頭でなくなるので、**B-5 が使えるならそちらを採る**

顔検出と併用し、顔が取れているフレームでは顔を、取れないフレームでは頭を使う。
これが「後頭部で 10 秒漏れる」型の唯一の対処になる。

#### B-5 骨格推定から頭を推定する

姿勢推定（COCO 17 点や MediaPipe Pose など）は、**顔の見た目ではなく体の構造**から
関節位置を出す。後ろを向いていても肩・首・耳は見えているので、体の配置から
頭の位置を割り出せる。顔検出器が原理的に無力な状況に、まだ手がかりが残っている。

**失敗の仕方が顔検出と補完的**なのが効く。

| 状況 | 顔検出 | 骨格推定 |
| --- | --- | --- |
| 後頭部・真横 | ✗ | ○ |
| 顔が小さい（引きの画） | ✗ | ○（体は大きく写っている） |
| 顔だけ遮蔽（手・マスク・髪） | ✗ | ○ |
| 極端な寄りで肩が画面外 | ○ | ✗ |
| 人が重なる | ○ | △（骨格が混ざることがある） |
| 暗所・逆光 | ✗ | △ |

上 3 行が現状の主な漏れ要因なので、和集合を取る価値が大きい。

**キーポイントから頭の箱をつくる**（下ほど頑健）：

1. 頭部キーポイント（鼻・両目・両耳）の外接矩形を拡大する。素直だが、これらが
   全部落ちると使えない
2. **肩から推定する**。肩の中点から、肩を結ぶ線に垂直な方向へ一定距離だけ進んだ
   位置を頭の中心とする。**頭のキーポイントが全滅しても効く**のがこれ
3. 両方が得られたときは**和集合**を取る（安全側）

2 には落とし穴がある。**人が横を向くと肩幅は画像上で縮む**（両肩を結ぶ線が
カメラの方を向くため）。横向きこそ隠したい場面なのに、そこで頭を小さく見積もって
顔が出る、という最悪の噛み合わせになる。

大きさの手がかりを肩幅だけに頼らないことで避ける。

- **胴の長さ**（肩の中点↔腰の中点）は、体を垂直軸まわりに回しても縮まない
- **そのトラックの直近の頭の大きさ**。急には変わらない
- これらの **max** を取る。安全側は常に「大きく見積もる」方向

**個体較正 — ここが精度を決める**

人体比率は統計値なので、そのまま使うと個人差と遠近で外れる。比率の初期値は
出発点にすぎず、2 節の評価素材で必ず測り直すこと。**が、A-1 で二段化してあるなら、
もっと良い方法が取れる。**

同じトラックの中で**顔検出が成功しているフレーム**では、顔の大きさと肩幅・胴長の
比が実測できる。その人・その画角での実測比を記録しておき、顔が取れなくなった区間では
それを使う。集団の平均値を、その人自身の測定値に置き換えられる。

これは全フレームの検出結果が先に揃っていて初めてできることで、**現状の単一パス構造では
実装できない**。B-5 の価値は A-1 と組みで最大になるので、順序を逆にしないこと。

あわせて、肩幅・胴長の変化からカメラとの距離の変化が分かる。人が奥に下がれば
マスクも自動で小さくなる（現状の hold は位置も大きさも固定）。

**注意点**

- 人が重なると骨格同士でキーポイントが混ざり、頭を別人の位置に置くことがある。
  可視性スコアとトラックの連続性で弾く。判断がつかないときは両方覆う
- 人物らしい形（ポスター・人形・鏡像）にも骨格が出る。マスクの用途では
  過剰マスクは安全側なので許容してよい
- 顔検出より重い。B-6 の段階化で、顔が取れないフレームだけに掛ける
- 候補：MediaPipe Pose（Apache-2.0・導入が軽い）、RTMPose（精度が高いが依存が重い）、
  YOLO 系 pose（AGPL-3.0）。**B-3 と同じくライセンスを先に確認する**

#### B-6 段階的な計算（速度対策）

上を全部、全フレームに掛けると実用速度から外れる。**安い検出を毎フレーム、
高い検出は必要なフレームだけ**に限る。

```
毎フレーム        YuNet（現状のまま）
  ↓ 何も出なかった／トラックが途切れた／確信度が低い フレームだけ
2 段目            解像度を上げる・TTA・アンサンブル
  ↓ それでも出ない
3 段目            頭部検出・骨格推定
  ↓ それでも出ない
                  段階 C へ
```

顔がちゃんと写っているフレーム（大多数）は 1 段目で終わるので、
平均コストは今とあまり変わらないまま、難しいフレームにだけ計算を集中できる。

---

### 段階 C — 最終防衛線

ここまでやっても覆えないフレームは残る。**「ほぼ 100%」を名乗れるかどうかは、
ここをどう扱うかで決まる。** 検出の改善では埋まらない最後の穴を、方針の選択で塞ぐ。

#### C-1 「人は居るのに顔が無い」フレームを見つける

顔が無いフレームには 2 種類ある。区別できないと何もできない。

- **本当に誰も写っていない**（風景・手元・物撮り）→ 何もしなくてよい
- **人は写っているが顔を取れていない** → 危険

判定材料：**骨格が検出できたかどうか（B-5。これが最も直接的）**、人物検出の結果、
前後のトラックからの推定（1 秒前に居て 1 秒後にも居る）、フレーム間の差分。

B-5 を入れてあれば、この判定はほぼ「骨格が有るのに顔が無い」の一言で済む。
骨格も顔も無ければ人は写っていない、と判断してよい。

#### C-2 覆えないフレームの扱いを設定で選ばせる

```jsonc
"mask": {
  // 顔があるはずなのに位置を特定できないフレームの扱い
  //   expand : 推定できる範囲を大きめに覆う（既定）
  //   blur   : 画面全体をぼかす（確実だが見た目が悪い）
  //   cut    : そのフレームを出力から落とす
  //   warn   : 何もせず報告だけする（現状の動作）
  "uncovered_policy": "expand"
}
```

`blur` と `cut` を選べば**漏れフレームは定義上ゼロになる**。見た目と引き換えに
確実性を買う選択肢を、人の手に残しておく。既定は `expand`。

#### C-3 出力を検査して閉じる（自動 QA として最も価値がある）

**書き出した `edited.mp4` を、もう一度アンサンブル検出器に掛ける。**
「出力から顔が 1 つも検出されない」ことを機械的に確認する。

- 入力ではなく**出力**を見るので、パイプラインのどこで漏れたかによらず穴を捕まえられる
- マスク画像自体が顔として検出される場合があるので、マスクを貼った位置と照合して除外する
- 検出されたら、その時刻を「要確認」として最優先で報告する

段階 B の重い設定を使ってよい。書き出しは一度きりで、検査は後追いでいい。
入力側でどれだけ頑張っても見落としは残るが、出力側の検査は最後の網になる。

---

### 段階 D — 人の確認を現実的にする

自動で 100% を保証することはできない。**最後は人が見る。**
その確認作業を「全編を再生する」から「疑わしい箇所だけ見る」に変える。

- **D-1 コンタクトシート**：危険度の高いフレームを縮小して並べた PNG を出す。
  1 枚で数十箇所を一度に見渡せる
- **D-2 確認用の抜き出し動画**：危険な時刻の前後 1 秒だけを繋いだ短い mp4 を出す。
  10 分の動画の確認が 30 秒で終わる
- **D-3 検出枠の焼き込み**：マスクの代わりに枠と確信度を描いた検証用出力。
  調整時に「なぜ外したか」が見える
- **D-4 報告の並べ替え**：`edit_report.json` の危険箇所を、時刻順ではなく**危険度順**に出す。
  上から見ていけば、危ない順に確認できる

危険度の目安：長い外挿の途中 > 補間で埋めた区間 > 確信度が低い検出 > 通常の検出。

## 5. 速度への影響

現状の書き出しは、H.264 符号化と毎フレーム検出が主なコスト。段階 A は検出回数を
増やさない（むしろ再書き出し時は減る）ので、影響はほぼ無い。段階 B は増やすが、
B-6 の段階化で「難しいフレームだけ」に集中させれば平均コストは抑えられる。

**具体的な数字はここに書かない。** 素材の解像度・長さ・機械で桁が変わる。
2 節の評価に処理速度も含めてあるので、実測して埋める。

速度が問題になったときの逃げ道を先に用意しておく：

- 解析パス（A-1）と書き出しを分けてあるので、解析だけ複数プロセスに割れる
- onnxruntime を GPU 対応にする（Windows なら DirectML）
- 書き出しの `preset` を落とす（画質と時間の交換）

## 6. 設定の追加案

既存の `mask` を壊さずに追加する。**既定値は現状の挙動に近づけ、
安全側に倒したい人が明示的に選べる形にする。**

```jsonc
"mask": {
  // ここまでは既存のまま
  "score_threshold": 0.5,
  "scale": 2.0,
  "hold_sec": 0.7,

  // 追加ぶん
  "interpolate": true,          // A-2 前後にアンカーがあれば補間して埋める
  "track_optical_flow": true,   // A-4 映像の動きで箱を運ぶ
  "gap_expand_per_sec": 0.6,    // 推定が続くほど箱を広げる割合（1 秒あたり）
  "detect_scales": [640],       // B-1 複数書くと各解像度で検出して統合
  "rotation_tta": [],           // B-2 例: [-25, 25]
  "detectors": ["yunet"],       // B-3 例: ["yunet", "scrfd"]
  "head_fallback": false,       // B-4 顔が取れないとき頭部検出に落とす
  "pose_fallback": false,       // B-5 顔も頭も取れないとき骨格から頭を推定する
  "pose_calibrate": true,       // B-5 顔が取れている間に体格比を実測して使う
  "uncovered_policy": "expand", // C-2 expand / blur / cut / warn
  "verify_output": true         // C-3 書き出し後に出力を再検査する
}
```

## 7. 決めておくべきこと

先に方針を決めないと 9 番以降で手戻りする。

1. **依存を増やしてよいか**。段階 B の効果は大きいが、`setup.bat` が重くなり、
   ネットワークが塞がれた環境での導入が難しくなる。現状は OpenCV と numpy だけで完結している
2. **モデルのライセンス**。この道具の配り方（個人利用か、公開か、業務か）で使えるモデルが変わる。
   B-3 と B-5 の注意書きを参照
3. **後頭部・真横を隠す必要があるか**。素材にそれが出るなら B-5（骨格推定）が要る。
   顔がこちらを向いている素材しか無いなら、段階 A だけで足りる可能性がある。
   評価素材（2.2）を集めた時点で判断できる
4. **隠しすぎをどこまで許すか**。被覆率を上げる施策はほぼ全て過剰マスクを増やす。
   顔以外が隠れて映像が成立しなくなる線を決めておく
5. **カット判定への波及**。顔検出の再現率を上げると `cut.mode: any` での「顔なし」判定が減り、
   カットされる区間が減る（`pipeline.py:68-79`）。カット用（`cut.face_score_threshold`）と
   マスク用（`mask.score_threshold`）は設定上は分かれているので、**検出器を差し替えるときも
   この分離を保つ**。カットは false positive が困り、マスクは false negative が困る、
   という非対称があるため

## 8. この計画の限界

段階 D まで実装しても、**「見なくてよい」とは言えない**。言えるようになるのは
「見るべき箇所が全長の数 % に絞られ、そこを見れば足りる」までで、README の警告は残す。

C-2 で `blur` か `cut` を選べば漏れフレームは定義上ゼロになるが、それは
「顔が写っているかもしれないフレームを捨てた」だけで、検出できたわけではない。
確実性と映像の質は交換関係にあり、この計画はその交換を**人が選べる形にする**もので、
交換そのものを無くすものではない。
